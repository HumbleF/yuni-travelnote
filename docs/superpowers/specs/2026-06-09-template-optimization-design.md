# 旅行攻略模板优化设计文档

> 日期：2026-06-09
> 范围：模板结构重组 + 阅读体验优化 + 写作门槛降低
> 目标：保持信息密度不丢失，消除重复，提升旅途中可用性

---

## 设计哲学（不变）

- 信息密度第一，可执行性第二，文采靠边站
- 客观信息走表格化，提示/避雷/真心话走第一人称口语化
- 每个数字可验证，每条建议可操作

---

## 新结构：4 大块 + 速查卡

```
┌─ 速查卡（紧急联络 + 核心数字 + 交通速记）
├─ 决策块（一句话点评 + 关于城市 + 真实预算）
├─ 实操块（交通+预约 + 住宿 + 打包清单）
├─ 行程块（Day行程 + 景点分级 + 出片机位 + 美食三档）
└─ 避雷块（避雷集合 + 写在最后）
```

**阅读逻辑链：** 值不值得去 → 怎么准备 → 到了怎么玩 → 踩坑提醒

---

## 模块边界规则（防止信息重复）

| 信息类型 | 归属模块 | 不放在 |
|----------|----------|--------|
| 机场→市区怎么到、票价、时长 | 实操·交通 | 行程 Day 1 不重复 |
| 景点开放时间 / 门票 / 推荐时段 | 行程·景点分级 | 实操·预约只写"需提前预约的项目" |
| 餐厅人均 / 地址 / 排队 tips | 行程·美食三档 | 行程骨架表只写店名+人均 |
| 住宿选区 / 酒店推荐 / 价位 | 实操·住宿 | 行程 Day 不提住宿 |
| 单个景点的避坑 | 行程·景点分级"真心话"列 | 避雷块不重复单景点 |
| 全局性踩坑（签证/海关/骗局/时段） | 避雷块 | 不散落在其他章节 |
| 紧急电话 / 货币 / 时差 / 插头 | 速查卡 | "关于城市"不重复纯数字，只放背景描述 |

---

## 各模块详细设计

### 速查卡（最顶部，"关于城市"表格之前）

放在一句话点评之前，打开攻略立刻可见。只放**可操作数字**，不放背景描述。

```markdown
## 速查卡

| 紧急 | |
|------|------|
| 报警 | 110 |
| 救护 | 119 |
| 中国大使馆/领事馆 | +81-3-3403-3388 |

| 基本 | |
|------|------|
| 货币 | JPY · 1 CNY ≈ 21 JPY |
| 时差 | 北京 +1h |
| 插头 | A型 110V |
| 支付 | Suica / 现金 / PayPay |

| 交通速记 | |
|------|------|
| 机场→市区 | N'EX 成田特快 ¥3,070 / 1h |
| 市内 | Suica 起步 ¥170 · 24h券 ¥800 |
| 退税 | 单店满 ¥5,000 · 带护照 |
```

**写作规则：**
- 只放数字和关键词，不写完整句子
- 最多 3 个表格（紧急 / 基本 / 交通速记），每表最多 5 行
- 国内城市可省略"紧急"表

---

### 决策块

#### 一句话点评

与旧模板相同，但**移除"最大避雷"**（避雷信息统一到避雷块）：

```markdown
## 一句话点评

- **适合谁**：...
- **不适合谁**：...
- **最大亮点**：...
```

只保留 3 条。"最大避雷"移入避雷块首条。

#### 关于城市

与旧模板基本相同，但去除速查卡已覆盖的纯数字信息（货币汇率、时差、插头、紧急电话）。此章节专注**背景知识**：

- 城市概况（1-2 句，禁止废话）
- 签证要求（详细流程）
- 气候描述（适合穿什么）
- 通讯方案（eSIM / WiFi 具体产品+价格）
- 抵达方式概述（航班信息，不含市内交通细节——那些在实操块）

#### 真实预算

与旧模板相同，分项明细表 + 合计。标注年份和出发地。

---

### 实操块

#### 交通 + 预约购票（合并为一章）

旧模板"交通详解"和"预约购票实操"合并为一个章节，避免机场快线/交通卡重复出现。

结构：

```markdown
## 交通 + 预约

### 大交通

| 场景 | 方式 | 费用 | 用时 |
|------|------|------|------|
| 成田→市区 | N'EX | ¥3,070 (优惠往返 ¥4,070) | 1h |
| 羽田→市区 | 京急线 | ¥600 起 | 30min |
| ...

### 市内交通

| 方式 | 费用 | 适用场景 |
|------|------|----------|
| Suica | 起步 ¥170 | 地铁/便利店 |
| 24h券 | ¥800 | 当天多次坐车 |
| ...

### 需提前预约的项目

| 项目 | 平台 | 提前几天 | 操作要点 |
|------|------|----------|----------|
| 涩谷天空日落场 | 官网 | 3天 | 日落场热门，当日常售罄 |
| 吉卜力美术馆 | Lawson Loppi | 每月10日 | 极难抢 |
| ...

> 打车避坑 / iPhone 用户提示等放在本节末尾。
```

**写作规则：**
- "需提前预约的项目"只列需要提前操作的（门票、签证、限流入场）
- 不需预约的景点（如免费公园、神社）不在此出现——它们在行程·景点分级里
- 交通表不超过 8 行

#### 住宿

与旧模板相同：区域对比表 + 避雷区域 + 实名推荐 3 家。

#### 打包清单

与旧模板相同。按季节分段，**必带 / 季节特定 / 别带** 三段式。

---

### 行程块

#### Day 行程（骨架表 + 路线说明）

**改进核心：** 将旧模板中每格 200+ 字的长表格拆为两层：

**第一层：骨架表**（手机可扫描）

```markdown
### Day 2：涩谷 + 原宿

| 时段 | 地点 | 要点 |
|------|------|------|
| 10:00 | 涩谷天空 | 开门首批 · ¥2,500 |
| 12:00 | 涩谷十字路口 | Magnet 屋顶俯拍 |
| 13:00 | 表参道 AFURI | 柚子盐拉面 ¥1,200 |
| 15:00 | 明治神宫 | 免费 · 参道 10min |
| 17:00 | 竹下通 | 平日傍晚人少 |
```

**第二层：路线说明**（100-150 字，串联衔接逻辑）

```markdown
> **路线说明：** 涩谷天空出来步行 5min 到十字路口，沿公园通往北
> 走 15min 到表参道。午餐后从表参道尽头直接进明治神宫南参道（同
> 一条路），参拜完原路返回竹下通。全程步行无需坐车。
```

**写作规则：**
- 骨架表每格不超过 15 字（时段 + 地点 + 一个要点）
- 路线说明只写**景点间的衔接**（步行/坐车/方向），不重复景点详情
- 景点详情（门票/时段/真心话）统一在"景点分级"里
- 餐厅详情（菜品/排队建议）统一在"美食三档"里
- Day 行程中的餐厅只写"店名 + 人均"

#### 景点分级

三档结构不变：**必去 / 可去可不去 / 避雷**

表格列定义：

| 景点 | 推荐时段 | 门票 | 真心话 |
|------|----------|------|--------|

**"真心话"列承担单景点避坑功能**——底部避雷块不再重复单个景点的坑。

"避雷"档的"为什么避"列要写具体原因（价格不值/人多/体验差），不能只说"不推荐"。

#### 出片机位

与旧模板相同：按难度排序，每条写 **地点 + 具体位置 + 最佳时段 + 构图提示**。

#### 美食三档

三档结构不变：**老字号 / 网红打卡 / 街头平价**

**与行程骨架的边界：** 行程表只写"店名+人均"，美食章节写完整信息（招牌菜/排队建议/营业时间/真心话）。

---

### 避雷块

#### 避雷集合

**只放全局性踩坑**，不重复单个景点的避坑（那些在景点分级"真心话"列里）：

适合放在这里的内容类型：
- 签证/海关/入境坑
- 全城性的骗术/宰客
- 时段性踩坑（特定节日/赛事期间涨价）
- 支付/退税/小费 坑
- 文化禁忌

不放在这里的内容：
- "XX 景点不值得去"——属于景点分级·避雷档
- "XX 餐厅味道差"——属于美食三档·真心话

第一条建议放旧模板"一句话点评"中移出的"最大避雷"内容。

#### 写在最后

与旧模板相同：50-100 字第一人称真心话收尾。

---

## 写作优先级

降低新城市的发布门槛：

| 等级 | 章节 | 说明 |
|------|------|------|
| ★ 必填 | 速查卡、一句话点评、关于城市、行程骨架、景点分级、美食三档、交通+预约、住宿 | 8 个章节写完即可发布 |
| ☆ 推荐 | 真实预算、出片机位、避雷集合 | 让攻略从"能用"升级到"好用" |
| △ 可选 | 打包清单、写在最后 | 跨城市高度相似的可后补 |

## 不做的事项

- 不改变 Markdown 格式（仍是纯 .md，不引入自定义组件语法）
- 不改变 frontmatter schema（字段不增不减）
- 不改变网站渲染逻辑（模板优化是内容层面，不涉及代码改动）
- 不引入折叠/手风琴 UI（保持静态 HTML 简洁）
- 不做 PDF 导出 / 离线包（速查卡本身支持截图即用）
